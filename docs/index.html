Re-render with plain HTML or JSX, and the page

keeps focus and selection keeps what users typed moves keyed nodes instead of rebuilding them changes only what differs takes partial change-sets

defuss-morph compares new markup with the live DOM and patches the difference with native DOM calls. A node that exists before and after stays the same node, so focus, the text in an input and its event listeners survive the update. It needs no virtual DOM and no build step, works next to any framework, and runs on the server against happy-dom as well as in the browser. Bind a region to a store with reactive(), and every change re-renders it the same way.

Try the playground Read the API

Built by Aron Homberg (kyr0) (opens in a new tab), open source (MIT (opens in a new tab))

Move, never rebuild

Children are matched by key, then by id, then by tag. A matched node is moved with moveBefore() and patched in place, so its identity, focus and caret survive.

Typed input stays

An input keeps its live value and checked state unless the new markup sets them. A textarea that has focus keeps its content while you type.

Native event behaviour

JSX handlers such as onClick listen on the element itself, so order, stopPropagation() and non-bubbling events behave natively. Removing an element tears its handlers down.

Partial change-sets

With { diff: true } you send only the items that changed, addressed by key or id. Diff mode never removes or moves anything, which suits streamed and AI-generated updates.

Browser and server

HTML is parsed by the DOMParser of the target element's own document, so the same call works in a browser, in happy-dom and across windows. The library entry has no side effects.

One file, no build step

One <script type="module"> tag loads 8.5 kB gzip and exposes the API as window.df$. Bundlers get side-effect-free ESM and CommonJS builds with type declarations.

Patterns

Four patterns to start from

Render a region again whenever a store changes. Reach a rendered element through a ref. Let a parent control a component through the ref it passes. In pages written as HTML, reference the markup by selector. Each panel shows the source of the demo beside it; the demos run the copy of the library this site serves, and the page's tests drive every one of them.

reactive(config, target) renders config.render() into the target at once and again after every store change, by morphing it in. <Reactive> does the same inside a JSX tree: it renders a wrapper element and stays subscribed while the wrapper is in the document. With defuss-query, installReactive(df$) adds .reactive() to every selection. The three views listen to one defuss-store store: type a note into a row, then press +1 or Reverse.

createRef() returns { current: null }. When morph renders the element that carries ref={…}, it puts the element into current, and a morph that keeps the element keeps the ref on that same node. Read it in an event handler, in onMount or after the morph call: in the component body it still holds the element of the previous render, or null.

Live

There is no forwardRef() to call. A component takes an optional ref prop with a default createRef(), gives it to its root element and puts its API on ref.state. Without a ref from the parent, the component manages itself; with one, the parent calls the API. A component function runs again on every render of its parent, so its state lives on the ref here, not in the function body.

Live

When the markup comes from a server, a CMS or a template, name its parts with data-ref and select each once with defuss-query: a selection is the HTML counterpart of createRef(). .html() morphs, so a filtered list keeps the elements it still shows. Type into the filter: the items that stay are the same nodes.

    How it works

    Matching before creating, moving only what is out of order

    Both inputs end up as the same structure: an HTML string is parsed into a detached document and read back as plain objects; JSX already is one. Every new child first looks for a node among the target's children that it can take over. Matched nodes already in the right order stay where they are and only the others move, so swapping two rows moves two; only a child without a match is created, and whatever is left unclaimed at the end is removed.

    What survives a morph

    • Node identity

      A matched node is the same object afterwards. References you hold, WeakMap entries and third-party widgets attached to it stay valid.

    • Focus and selection

      A node is moved with moveBefore(), which keeps a focused input focused with its caret. Browsers without it get insertBefore(), after which morph puts focus and the selection back.

    • Uncontrolled form state

      Markup without value or checked leaves the live state alone. Markup that declares them, or a VNode with checked: false, sets it.

    • Event listeners

      Listeners you added with addEventListener stay on surviving nodes. An HTML string cannot declare handlers, so registered JSX handlers stay too.

    • Comments

      HTML comments are matched and patched like text, so morph(el, el.innerHTML) changes no node.

    • Lifecycle hooks

      onMount runs after insertion, and again after each morph that patches the element with an onMount; onUnmount runs once when the element leaves the document, with the handler of the latest render, and receives the element.

    Ordering rules

    1. 01

      Full state by default

      A plain morph() describes all children: whatever the input does not mention is removed.

    2. 02

      Nested morphs queue

      A morph started from inside another morph on the same element or a descendant waits; the latest request runs when the outer morph returns.

    3. 03

      The latest content wins

      A morph issued while a transition runs applies at once and also replaces the content that transition will apply, so it never ends on stale markup.

    4. 04

      Shadow roots are targets

      An element with an open shadow root is morphed inside it. Custom elements (tag names with a hyphen) keep their light DOM as the target, for slotted content.

    API

    One function for most pages, primitives for frameworks

    Most code needs only morph(). The declarations ship as dist/index.d.ts; the source of truth is src/index.ts.

    morph(el, newContent, options?) makes the children of el match newContent: an HTML string, a VNode, an array of VNodes or plain text. It returns undefined and finishes synchronously, unless a transition is requested; then it returns a Promise that resolves when the transition has finished.

    transition.durationnumber (ms)300Length of each animation phase.
    transition.easingstring'ease-in-out'Any CSS timing function.
    transition.delaynumber (ms)0Wait before the transition starts.
    transition.target'parent' | 'self''parent'Which element is animated. With 'parent', an element that has no parent is morphed without animation.
    transition.styles{ enter, enterActive, exit, exitActive }by typeYour own CSS property maps for the four phases (not used by fade).

    With { diff: true } the input is a change-set for the direct children of el. Each item names its node by key (preferred) or id. A matched node gets the declared attributes merged in, and its children replaced only if the item declares children. An unmatched item is appended. Nothing else is touched.

    ItemEffect
    Matches an existing childPatched in place: declared attributes set, undeclared ones and registered handlers kept. A different tag replaces the node.
    Matches nothingAppended at the end. It needs a tag, because it has to be created.
    No key or id, or plain textThrows an Error: there is no unambiguous node to address.
    Top-level comment, whitespaceSkipped. Comments inside items are morphed.
    Child not mentionedUntouched: identity, order, attributes and listeners stay. Use a full morph() to delete.

    Store-driven rendering, refs and a JSX runtime, all built on morph(). A store is anything with subscribe(listener) that returns an unsubscribe function, such as a defuss-store store or computed(). The Patterns section above runs each of these.

    Three rules follow from treating markup that does not mention something as "leave it alone".

    HTML cannot uncheck a box

    Markup without checked means "not controlled", so a box the user ticked stays ticked. The same holds for an input's value. To set the state explicitly, send a VNode: in diff mode, morph(el, [{ attributes: { id: 'terms', checked: false } }], { diff: true }).

    Inline on-attributes are not removed

    Attributes whose name starts with on, such as onclick="…", are never removed by a later morph. Attach behaviour with addEventListener or JSX handlers instead of inline attributes.

    Diff mode cannot delete

    A change-set only patches and appends. Removing a node, or reordering, needs a full morph() of the parent.

    Install

    Add it to your page or your app

    Load one file from the CDN, install the package, or copy the built file into your assets. Then morph, or give your coding agent the defuss-morph skill.

    From the CDN

    The bundle registers the API as window.df$, or you import it as a module. An existing df$, for example from defuss-query, is extended rather than replaced.

    With a package manager

    Pins the version, works offline and lets your bundler tree-shake. The package entries register no global.
